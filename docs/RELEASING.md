# Releasing Vyder

This is the maintainer checklist for a release. It assumes a Windows machine for the
primary desktop installers and a connected arm64 Android device for smoke testing.

## 1. Bump the version

Update the same version in:

- `package.json`
- `src-tauri/Cargo.toml`
- `src-tauri/tauri.conf.json`
- `CHANGELOG.md`

`src-tauri/gen/android/app/tauri.properties` is regenerated by the Tauri CLI.

## 2. Run the checks

```bash
pnpm install --frozen-lockfile
pnpm check
pnpm build
cargo fmt --manifest-path src-tauri/Cargo.toml --all -- --check
cargo check --manifest-path src-tauri/Cargo.toml
```

## 3. Build the desktop installers

```bash
pnpm desktop:build
```

Copy the NSIS and MSI installers from `src-tauri/target/release/bundle/` into
`release/`. Do not commit `release/` or `src-tauri/target/`; they are ignored by git.

Smoke-test the installed app:

- inspect a short public video;
- download to a clean folder;
- pause, resume, cancel, retry;
- open and reveal the finished file;
- delete the library row and the file.

## 4. Build the Android APK

Use a real release keystore before publishing outside a test group. The current
`release/android` APK is debug-signed for sideloading only.

```powershell
$env:JAVA_HOME = "C:\Program Files\Android\Android Studio\jbr"
$env:ANDROID_HOME = "$env:LOCALAPPDATA\Android\Sdk"
$env:ANDROID_SDK_ROOT = $env:ANDROID_HOME
$env:NDK_HOME = "$env:ANDROID_HOME\ndk\28.2.13676358"
$env:Path = "$env:JAVA_HOME\bin;$env:ANDROID_HOME\platform-tools;$env:Path"

pnpm tauri android build --apk --target aarch64 --ci
```

If Windows refuses the Tauri symlink step, follow the prebuilt-`.so` fallback in
[MOBILE.md](../MOBILE.md).

Verify the package before uploading:

```powershell
aapt dump badging path\to\app-release.apk | Select-String "package:|native-code|sdkVersion|targetSdkVersion"
```

The expected package is `com.zubairkhan.vyder`, with `arm64-v8a` and
`extractNativeLibs=true`. Install it on a physical device and check:

- the launcher icon is the green Vyder mark;
- the Paste button fills a copied link without a keyboard shortcut prompt;
- a download continues after pressing Home and shows a progress notification;
- pause leaves a `.part` file, and resume finishes the same file;
- the Library can open the result in an external player.

## 5. Hashes and release notes

From `release/`, generate hashes with PowerShell:

```powershell
Get-FileHash Vyder_0.1.0_x64-setup.exe -Algorithm SHA256
Get-FileHash Vyder_0.1.0_x64_en-US.msi -Algorithm SHA256
Get-FileHash android\Vyder-0.1.0-arm64.apk -Algorithm SHA256
```

Write them to `release/SHA256SUMS.txt`, update `release/README.txt`, and attach the
three files to a GitHub release. Never commit the binaries; upload them as release
assets.

## 6. Publish

```bash
git tag v0.1.0
git push origin main --tags
gh release create v0.1.0 `
  release/Vyder_0.1.0_x64-setup.exe `
  release/Vyder_0.1.0_x64_en-US.msi `
  release/android/Vyder-0.1.0-arm64.apk `
  --title "Vyder 0.1.0" `
  --notes-file release/RELEASE_NOTES.md
```

Mark the release as a pre-release if the APK is still debug-signed or the build has
not been tested on the minimum Android version.

## 7. Clean up

```powershell
Remove-Item -Recurse -Force src-tauri/target
Remove-Item -Recurse -Force src-tauri/gen/android/app/build
Remove-Item -Recurse -Force src-tauri/gen/android/build
Remove-Item -Recurse -Force dist
```

Do not remove the source icons, Android Kotlin files, or `release/README.txt`.
